## Core rule

The story is shown **with illustrations throughout the text**, not as a long prose block with a gallery at the end.

Images are inserted at narrative anchors. They must help the child:
- understand the place/action;
- recognize recurring characters and horses;
- feel the emotional beat;
- understand a choice before selecting it;
- see the selected consequence afterward.

Do not bake Russian text into the artwork. UI text/localization remains separate.

## Asset model

Three visual types:

1. **Cover** — one story cover.
2. **Shared story illustration** — shown on every path.
3. **Choice illustration** — two alternative assets for each decision. Both appear as choice-card art; after selection, the chosen asset may expand/full-width with its `resolution_text`.

This avoids creating extra post-choice art while still making the child’s choice visibly different.

### Total production set

- 1 cover
- 17 shared story illustrations
- 8 choice illustrations (2 × 4 choices)

**Total assets: 26.**

On one actual playthrough the child sees:
- 1 cover
- 17 shared illustrations
- 4 selected choice illustrations

**22 illustrated moments** across the full story.

That is appropriate for the current ~3,000-word V3: roughly one visual beat every 140–170 words, with denser imagery in action-heavy sections.

# App rendering rules

## 1. Images belong to text anchors

Do not render all part images as a gallery at the top.

Each image slot is attached to a stable narrative anchor/id. Example:

`part_3_eastern_forest / after:event_road_book_lost`

The player inserts the image after that beat.

## 2. Choice art has two jobs

At a decision:
- show both A/B images as choice cards;
- after confirmation, retain/expand only the selected image with the selected `resolution_text`;
- do not show the unselected result afterward.

## 3. Resume behavior

Persist:
- current part;
- current narrative anchor;
- selected choice id if one exists;
- whether the selected resolution has already been shown.

On app restart, never replay a different illustration/resolution.

## 4. Illustration continuity state

Each image request must receive:
- character refs;
- horse refs;
- location ref;
- current costume/damage state;
- current props;
- choice id when branch-specific;
- exact bandit symbol reference when applicable.

## 5. No accidental canon

Generated background details do not become canon unless separately approved.

Especially do not invent:
- new royal symbols;
- new horse markings;
- new wounds;
- extra weapons;
- magic;
- bandit identities;
- city names/signage.

## 6. Production format recommendation

For mobile:
- shared narrative art: landscape/wide **4:3 or 3:2**, displayed full width;
- choice cards: same scene language, crop-safe so they can render side-by-side; keep main action centered;
- cover: portrait-friendly separate crop/composition.

Keep important faces/actions away from edges so one source image can support responsive cropping.
