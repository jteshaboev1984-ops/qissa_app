# QISSA: controlled single-E1 dual-branch editorial acceptance

**Status: protocol prepared, NOT executed.** No workflow, paid provider invocation, runtime toggle, secret or credential is created by this document. Use only after the user approves the concrete paid scope and a reviewed runner/harness is available. A technically GREEN session is not a family-beta editorial PASS.

## Scope and immutable assertions

- Confirm the **exact deployed main SHA**, active `story-generate` Edge Function source SHA, `verify_jwt=true`, and service-role runtime flag OFF before generating anything. Confirm the 180-second admission lease has already been deployed (`docs/qissa/ai/10_STORY_AI_RUNTIME_LEASE_RUNBOOK.md`). Avoid provider TTS, escalation, additional worlds/languages or automatic paid retries beyond the built-in bounded repair behavior.
- One synthetic UZ age 5–7, `cozy_forest`, bedtime-series, custom hero Malika. Allow **exactly three provider-eligible `story-generate` requests total**: one E1, one E2 after A and one E2 after B. Never rerun E1 merely to build B. Failed generation consumes its slot; stop and investigate rather than quietly paying again. Built-in Architect/Narrator/Safety/repair can make multiple provider HTTP calls per eligible request; response `X-QISSA-Provider-Calls` is diagnostic and **not** an invoice or strict HTTP-call bound. Confirm an explicit financial ceiling separately before enabling anything.
- The shared E1 `story_text`, title and two choice/bridge payloads must be byte-identical between branch preparations. Only per-installation/session IDs may be remapped for independent persistence. Never change any E1 branch facts, canon or selected-choice payload when cloning. Each branch has its own random UUID installation, independent 64-hex `installationAuth` from a cryptographically secure RNG, distinct series/session IDs, profile, and separate cleanup checks. Never print credentials or public keys in logs.
- Use real production `applyEpisodeToSeriesState` followed by `applyChoiceToSeriesState` (see `src/lib/memoryAgent.ts`) rather than hand-merging patches: E1 top-level canon must be applied first, then **only** the selected branch patch. Validate state/choice history isolation (A has only A; B only B), canonical hero name, original supporting cast, saved `resolution_text`, and episode index 2. If scripting cannot import these exact pure helpers, independently verify field parity against them before paying.

## Safe test lifecycle

1. **Provider-free preflight:** verify official CI/Story Core GREEN on the final PR SHA; confirm `main`/deployment SHA match and DB runtime flag OFF. Review harness for its exact three-call maximum, no unbounded retry, no secret echo, correct `installationAuth`, timeout and cleanup. Do not reuse `scripts/smoke-closed-beta-e2e-live.mjs` as-is: it loops through 12 fallback scenarios, expects `safe-fallback`, does not supply installationAuth, and is not a real dual-branch provider test.
2. **Operator grants one short admission window** using service-role DB `enabled=true, updated_at=clock_timestamp()` immediately before an approved provider request. No background lease renewal. A run must abort safely if its permit expires; if another request is needed, verify scope, accounting, OFF/expiry and authorize a new window deliberately. The lease blocks new calls after three minutes but does not interrupt admitted in-flight work, physically set the Boolean OFF, or replace explicit cleanup.
3. **Generate ONE E1** and require source `openai-structured`, safety approved, correct language/hero, no leaked `{{HERO}}`, exactly two acceptable options and a bridge for each. Record unique synthetic test ID, response metadata, initial/final word counts, repair flags and the complete child-visible E1 + both choice/bridge texts in controlled evidence. If fallback or invalid story occurs, stop: no synthetic replacement falsely labeled Luna.
4. **Prepare independent branch states from that exact E1.** In both installations, arm cleanup **before** the first `sync_generated`, since it may create a profile before failing. Supply the correct 64-hex installationAuth in EVERY story-state call. Sync the same E1 content to A/B with only its series/session identity adapted, apply the E1 top-level patch via `applyEpisodeToSeriesState`, then confirm choice A or B separately via `confirm_choice` and verify `load_current` with credential. Do not copy A history into B.
5. **Generate each E2 exactly once** under its own correctly selected state. Require `openai-structured`, Episode 2 ID/series match, safety approved, zero structured choices, no unresolved phantom choice, no replay of already-shown `resolution_text`, no new unrelated plot, original local goal visibly resolved, calm ending, and no cross-branch canon/name leakage. Persist E2, reload and compare relevant state/episode. Check that both branches have substantially different child-visible scene/action/discovery/interaction, not just changed adjectives or JSON fields.
6. **Always-run cleanup and OFF:** in `finally`, immediately set `enabled=false, updated_at=clock_timestamp()` using a trusted operator context; verify the authoritative DB row. For EACH installation, call authenticated `delete_profile_data`, then authenticated `load_current` expecting null, and verify test credentials/profile absence through approved read-only DB checks. Record cleanup failures as NO-GO. Remove temporary triggers/scripts after completion. If runner/session dies, the lease prevents new provider admission after expiry, but human/operator must still reset the stored ON Boolean and inspect data.
7. **Independent editorial review:** read two complete child-facing sequences E1 → choice A/B → matching bridge → its E2. Apply all 12 rubric dimensions separately to EACH; record 0/1/2, total >=20/24, no hard fail, no required-dimension 0, 2–4 specific literary notes, independent Uzbek editor and parent/child read-aloud observations. Mark `ITERATE`/`REJECT` honestly if evidence or reviewers are missing. Do not treat CI, safety or one strong branch as sufficient qualification.
