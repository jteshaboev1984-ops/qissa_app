## Принцип работы

Цель — единая средняя визуальная насыщенность `3–5` кадров на читательскую серию, около 4 в среднем, с драматургическими обоснованиями; нет обязательства вставить кадр на каждое заранее заданное число слов. Утверждён план объёма `29 + 19 + отдельная обложка`, **не** конкретные изображения.

Видимые изображения: общие для обеих веток + выбранный вариант каждой альтернативной развилки. Не суммировать одновременно обе альтернативы как две увиденные картинки. Не дублировать уже одобренный кадр, если новый не привносит важной информации.

## Обязательная карточка кандидата

| Поле | Что записать |
|---|---|
| Точка очереди | `S{season}E{episode}-A{N}` (внутренний кандидат, не финальный asset_id) |
| Приоритет и этап | `stage_1` / `stage_2` / `season_4_cover` |
| История и версия | `story_id`, `story_version` исходного authored JSON |
| Исходная часть | `part_id` и место до/после 9 виртуальных разрезов |
| Фаза | `story_text`, `post_choice_text`, либо согласованный `resolution_text` |
| Якорь RU | **Точное целое предложение/абзац** `after_text` из русского JSON |
| Якорь UZ | Соответствующий **точный** локализованный абзац, не машинный перевод навскидку |
| Сюжетный момент | Только происходящее/установленное в тексте; кто/где/когда/что видно |
| Драматургическая функция | Новое место, герой, опасность, открытие, эмоциональный поворот, кульминация или развязка |
| Визуальные эталоны | Конкретные одобренные reference-файлы (включая реальные пиксели), канон World Bible V2 |
| Композиция / ограничения | План камеры, соотношение сторон, одежда, время суток, табу на спойлер/современные предметы |
| Доступность | `shared` для обеих веток по умолчанию; `branch` только после явного согласования |
| Приёмка | `planned → prompt_approved → generated → owner_approved → stored → runtime_integrated → qa_passed` |
| Тех-ассеты | final `asset_id`, PNG master path, WebP path, bytes, dimensions, SHA-256, public URL, manifest/CI refs |

**Критично:** `after_text` для новой картинки выбирать там, где сцена уже раскрыта ребёнку, чтобы иллюстрация не спойлерила будущую часть или ещё не выбранное решение.

## Интеграция в приложение: только после приёмки изображения

1. Внести согласованный уникальный slot/asset ID и anchored placement в соответствующий authored package RU и UZ overlay. Изменение изображения **не** повод менять литературные абзацы, `story_id`, `story_version`, `part_id`, `decision_id`, `choice_id`.
2. Учитывать виртуальные разрезы `sevenRoadsReadingSeries.ts`: один исходный `part_id` может располагаться в двух пользовательских сериях. Проверить, что изображение оказалось **в правильной серии**.
3. Разместить утверждённые PNG-мастера в постоянной Library и WebP-дериватив в указанном сторидже. При успешной фактической загрузке проверить GET/MIME/размер/SHA-256; нельзя выдавать запланированный URL за загруженный.
4. Дополнить `src/data/authoredStoryAssets.ts`, художественные инвентари и очередь. Сохранить видимость по ветке и защиту галереи от спойлеров.
5. Запустить `npm run check:reading-series-30`, `npm run check:four-seasons`, `npm run typecheck`, `npm run build`, существующий art-специфичный QA и browser smoke при наличии среды. Отдельно проверить RU/UZ и мобильный экран 360/390/430 px.
6. Не публиковать изменения в production и не объединять PR без отдельного решения владельца. Новый этап художественной работы можно продолжать в том же PR либо в отдельной согласованной ветке, не перезаписывая чужие изменения.

## Дополнительный QA-гейт после аудита S4E8 17.11.2026

Прежде чем принимать сложный боевой/многоперсонажный общий кадр, **визуально сравнить реальную фактическую галерею из PNG с утверждённым предыдущим и последующим кадром**, а не только с текстовым описанием или названием референса. Проверить: одна пространственная схема и линия горизонта; кто с кем сражается (численность и группировки из литературного источника); пропорции людей, лошадей и повозки; положение укрытия; пропсы/архитектуру и одежду; отсутствие спойлеров. Если геометрия не подтверждается, новая генерация не принимается, файл с `APPROVED` в имени не означает утверждение. Отзыв владельцем художественной приёмки должен сразу исключать asset из `ART_QUEUE` и запрещать его upload/runtime. Подробный пример: [S4E8 spatial QA](S4E8_A01_SPATIAL_CONTINUITY_AUDIT_2026-11-17.md).
